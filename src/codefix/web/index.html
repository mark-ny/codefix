How it works

Paste code → Analyze lists problems. Tick the ones you want fixed (safe fixes are applied automatically unless you untick that box) → Fix selected + safe. The result replaces the text box; Undo brings back the previous version. Every result is parsed, compiled and checked to keep all functions and classes before you see it.

Files & folders → type a path (or Browse) → Review → choose rules → Preview (no writing) or Apply (backup → atomic write → your tests → automatic rollback if they fail). codefix undo FILE restores a backup from the terminal too.

Teach CodeFix → give it an example of bad code (and what it should become). It learns a $variable pattern, tests it, and saves it as a normal rule that also works in the terminal (codefix review, fix, …). Share rules with Export/Import.

What the badges mean

auto-fix safe, high-confidence: applied automatically if enabled. needs your OK review-level: only when ticked. needs explicit approval risky: only when ticked, and for files, tests must be configured and pass. report only no automatic fix or confidence too low. blocked never applied.

Safety

  • The server listens on this computer only and requires a per-session token.
  • It can only touch folders it was started with (--root, default: where you launched it).
  • Nothing is written without a confirmation; a backup is always made first (.codefix/backups).
  • Rules you teach are data, not code: they cannot run anything.

Shortcut: Ctrl/Cmd+Enter analyzes.
